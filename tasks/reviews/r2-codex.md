Found three real defects; the first is a host-secret escape.

- Critical — the relay can Read arbitrary host files. [agents/agy.md](/home/matt/Projects/claude-code-model-policy/.worktrees/agy-offload/agents/agy.md:4) gives it `Read`, but the installed matcher excludes `Read` ([install-merge.mjs](/home/matt/Projects/claude-code-model-policy/.worktrees/agy-offload/install-merge.mjs:22)). Thus a prompt-injected relay can `Read ~/.ssh/id_*`, `~/.claude*/settings.json`, or install files before it invokes bwrap, then relay contents. The hook would deny Read if invoked ([gate.mjs](/home/matt/Projects/claude-code-model-policy/.worktrees/agy-offload/hooks/gate.mjs:43)), but it never receives it. Fix: include `Read` in the matcher and allow only the gate-associated result file; ideally preallocate/bind its output path in the grant.

- High — upgrading a 0.3.0 install can change unrelated hooks’ scope. Matchers belong to a hook *group*, but the upgrader rewrites the whole group matcher when it finds this package’s gate hook ([install-merge.mjs](/home/matt/Projects/claude-code-model-policy/.worktrees/agy-offload/install-merge.mjs:61)). Confirmed with a 0.3-style fixture: a group containing gate plus `custom-hook` changed from `Agent|Workflow` to `Agent|Workflow|Bash|Write|Edit|NotebookEdit`; the custom hook now runs on all four new tools and may deny, emit output, or add latency. Fix: if a group contains non-package hooks, remove/migrate only the package hook into a dedicated new group; leave the original matcher untouched.

- Medium — the checkout/task authorization has a same-UID TOCTOU. The wrapper validates `realpath(cwd)` and the task, consumes only the JSON grant, then later resolves those pathname strings again for `cp`, `git -C`, and bwrap ([agy-relay.sh](/home/matt/Projects/claude-code-model-policy/.worktrees/agy-offload/bin/agy-relay.sh:36), [agy-relay.sh](/home/matt/Projects/claude-code-model-policy/.worktrees/agy-offload/bin/agy-relay.sh:117)). A concurrent same-user process can rename the granted `.worktrees/x` after validation and replace it with a symlink to another directory; bwrap follows the new source and grants it edit access. Grant-file replay is correctly protected by `0700`/`0600`, 48-hex IDs, and atomic rename, but this path race remains. Fix: pin task and checkout with opened descriptors (no-follow), mount a stable internal destination such as `/workspace`, and copy the task from its pinned FD.

For the requested fast-path check: the gate itself stays silent and does no ledger/session write for valid non-agy calls, but every main-thread Bash/Write/Edit now starts Node and loads policy before returning ([gate.mjs](/home/matt/Projects/claude-code-model-policy/.worktrees/agy-offload/hooks/gate.mjs:30)). I measured 1.16s for 30 Bash payloads (~39ms/call). The shared-group upgrade issue above can additionally change behavior of other hooks.
